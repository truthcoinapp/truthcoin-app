# Truthcoin App v0.1.0

The first release: a desktop app for your own Truthcoin wallet, with a phone page that pairs to it.

**Early software.** Reviewed by automated security reviews, not a professional audit. Keep only what you are
trading in it. Not made by L2L.

## What it does

- **Runs the Truthcoin node for you.** With BitWindow's eCash running (it starts the enforcer), the app downloads
  L2L's `truthcoin_dc` v0.19.0 from L2L's GitHub release, keeps it only if its SHA-256 is the one pinned in the app,
  runs it in its own folder on its own ports, and stops it when you quit.
- **Wallet:** new recovery words (shown once, three asked back) or old ones (the app looks through the chain for the
  wallet's coins). Deposit from BitWindow's eCash wallet, receive, withdraw to eCash.
- **Markets:** chances, volume, what you hold and what you paid. Get a price, then buy or sell with a cap that
  includes the miner fee. Waiting trades show the coin they hold; a stuck one can be cancelled. A one-coin balance can
  be split into four, so several trades can wait at once.
- **Create a market:** yes/no, one of several, or a number; the voting period; the depth; every cost before you
  confirm.
- **Your phone:** pair by QR code and a code compared on both screens. The phone sees markets, positions and balance,
  gets prices and trades within a daily limit; bigger buys wait for you on the desktop. Sealed messages over public
  Nostr relays: nothing is hosted for it. The phone page is at https://mblowes.github.io/truthcoin-app/.
- **Update check:** only a release signed with this app's key counts.

## Not in this release

Voting screens, keeping the phone connected while the app is closed, Face ID approvals, notifications on the phone,
Windows.

## Known limits

- The Truthcoin node has no RPC login and stores its seed unencrypted (README, "What the app can't protect").
- Trades go through with the next Truthcoin block, about every 10-17 minutes on eCash beta.
- A withdrawal waits for eCash miners to approve its bundle, over many blocks.
- macOS: not notarised; open it the first time with right-click › Open.

## Security self-audit

Before this release, the desktop app and the protocol had an adversarial review and two re-reviews, and the phone page
a review and a re-review, by AI reviewers; then a UX walk-through of both, and a security pass over its fixes. What
they found, and what changed:

- **The node's wallet could be found by a web page.** The node's RPC has no login and allows every origin. The app now
  puts the wallet's calls on a random port and, on Linux, a random address in 127.0.0.0/8. (On macOS it is 127.0.0.1:
  the README says what that means.)
- **A phone's limit couldn't be stretched:** sells count at face value (a sat a share), a buy's cap is tied to the
  price, held trades expire after an hour, a phone has at most 3 trades held and 3 waiting, and every trade that may
  have reached the node counts.
- **Pairing:** the comparison code now covers a nonce the computer picks after the phone's keys are fixed, a second
  phone on the same code makes the pairing refusable only, pairing links expire within 10 minutes, and the phone asks
  you to confirm you allowed it on your computer.
- **Repeats never trade twice:** a request id is claimed before any work, by one handler for the link's life, and a
  trade the node may have taken is never reported as "not done".
- **Robustness:** unreadable records are set aside, never written over, and phones can't trade until you look; one
  copy of the app per data folder; a log trim that could have stopped the app at every launch; relay floods can't
  starve the link; the node no longer inherits `RUST_LOG` (which could have logged the recovery words).
- **Release builds run only on eCash beta**, checked by eCash beta's fork block.

Open, and said so: the node itself (no RPC login, unencrypted seed); the phone page's origin is shared by every GitHub
Pages site of the account (none other exists, and none may).
